# Getting Skis onto the App Store

Everything here is prepared. What is left needs a Mac, and the enrolment needs
starting well before you need it.

## Order of operations

**Start today, regardless of everything else: [enrol in the Apple Developer
Program](https://developer.apple.com/programs/enroll/).** $99/year. As an
individual it is usually same-day. As a company it needs a D-U-N-S number and
can take one to two weeks, so it is the long pole and nothing else on this list
depends on it being finished.

While that runs, nothing here is blocked.

## 1. On the Mac

```bash
git clone <this repo> && cd Skis
npm install
npm run build
npx cap add ios          # macOS + Xcode only, once
```

That generates `ios/`, which is gitignored: it is derived, and regenerating it
is safer than merging it.

## 2. Icons and launch screen

`assets/` holds the masters, generated by `npm run icons`:

| file | what it is |
|---|---|
| `assets/icon.png` | 1024x1024, **opaque, no rounded corners**. Apple rejects an App Store icon with an alpha channel, and iOS draws the corner mask itself. |
| `assets/icon-foreground.png` | inset so it survives a circular crop |
| `assets/splash.png` | 2732x2732, mark centred, safe under any crop |

```bash
npx @capacitor/assets generate --ios
```

That fills in every size Xcode wants. Do not hand-cut them.

## 3. Files to copy in

| from | to |
|---|---|
| `ios-setup/PrivacyInfo.xcprivacy` | `ios/App/App/PrivacyInfo.xcprivacy`, then add it to the **App** target in Xcode |
| `ios-setup/Info.plist.additions` | merge into `ios/App/App/Info.plist` |

The location string in `Info.plist.additions` is not optional. iOS terminates
the app on the first location request without it, and App Review reads it.

## 4. In Xcode

- **Signing & Capabilities**: pick your team. Bundle identifier is already
  `ski.skis.app` in `capacitor.config.json`; change it there, not in Xcode, or
  the next `cap sync` will overwrite you.
- **Deployment target**: iOS 15 or later.
- **Version and build**: `MARKETING_VERSION` matches `package.json`;
  `CURRENT_PROJECT_VERSION` goes up by one every upload, forever.

Then Product → Archive → Distribute → TestFlight.

## 5. Before the listing

**Ski it on a mountain first.** The GPS auto-advance is verified against
simulated coordinates in `npm run features`, not against a real phone on a real
chairlift with a real cold battery. That is the one thing no test here covers.

## 6. App Store Connect

- **Privacy policy URL**: `https://<your-site>/privacy.html`
- **Support URL**: `https://<your-site>/support.html`
- Both are in `public/` and ship with the site. **Set the contact address in
  them first**: they both say `CONTACT@EXAMPLE.COM`.
- **App Privacy**: answer **Data Not Collected**. That is genuinely true, which
  is rare, and worth not giving away by accident. The only outbound requests
  are map tiles, which carry no identifier and no user data.
- **Age rating**: 4+.
- **Category**: Navigation, with Sports as secondary.
- **Screenshots**: at the iPhone sizes App Store Connect asks for at the time.
  Confirm the current requirement there rather than trusting a list in a
  README; Apple changes it.

### Review notes worth writing

A reviewer in Cupertino gets *"You're 9,000 km from Monterosa Ski"* on first
launch, which is correct behaviour and looks like nothing works. Tell them:

> Skis plans a day's skiing around a time budget rather than routing point to
> point. The reviewer is not near the resort, so tap the resort on Home, then
> Go skiing, then Plan, and pick a start and finish from the lists. Routes are
> solved on-device and work in airplane mode. Location is used only to set the
> starting point and to advance the route while skiing.

That also answers guideline 4.2: the offline solver and the GPS navigation are
what make this an app rather than a website in a wrapper.

## The thing that should gate a public listing

`src/resort.js` is still hand-typed from memory. Run names, lift ride times and
**last-lift times** are plausible fiction. The app's promise is *"Last lifts are
built in. Nothing will strand you."*

Shipping that promise on invented data is the one thing here that could hurt
someone, and guideline 1.4 covers apps that risk physical harm. `npm run resort`
replaces it with real OpenStreetMap data; last-lift times are not in OSM and
have to come from the resorts. Until then, TestFlight with people who know, not
a public listing.
